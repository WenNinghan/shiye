## 五、设计方案

### 5.1 推荐方案

1. **默认阅读。** 卡片以清晰数学排版为主，显示“待核对/已核对”。默认不展示源码；不能渲染时显示明确提示和原图，不把错误代码伪装为正常公式。
2. **对照与放大。** 使用已有 page image 和 bbox 在浏览器内展示原图局部。对照窗桌面并排、手机上下排列；支持放大和关闭，保留键盘焦点行为。裁图失败可回到整页查看，不丢源图。
3. **修改公式。** 点击后再加载 MathLive，默认提供可视化输入、分式/根式/上下标/积分/求和/矩阵模板及虚拟键盘。用户编辑的是数学排版，不是源码。采用局部草稿：应用才更新父级块；取消不改原值；未应用的修改离开时需确认。
4. **数据一致。** 应用修改同步更新 latex/text，清除 verified，保留 original_text；清空和无效公式不能勾选为已核对。不会自动化简、求解或改写数学含义。源码高级编辑和可视化编辑共用同一份保存值。
5. **图片导出。** 用 html-to-image 对当前已排版公式生成 PNG，默认为白底清晰图片，只包含公式不含按钮/原图/源码。等待字体就绪，导出完整内容而不是滚动窗口的可见部分。提供预览和显式下载入口；处理失败、超大公式与临时 URL 清理。
6. **Word 导出。** 复用现有整份 Word 导出；通过真实导出文件检查编辑后的公式仍为可编辑数学对象。无法转换的结构沿用后端警告，不宣称所有 LaTeX 都支持。
7. **本机资源。** 两个依赖从 npm 安装并锁版本。字体随本机前端打包，编辑器和 PNG 工具按需加载，不接入 CDN、云计算或外部识别接口。若所选版本仍产生外部请求，处理后再验收，不放宽 CSP。

官方依据：[MathLive React 接入](https://mathlive.io/mathfield/guides/react/)、[本地依赖与字体打包](https://mathlive.io/mathfield/guides/integration/)、[矩阵编辑](https://mathlive.io/mathfield/matrix/)、[html-to-image PNG 与字体选项](https://github.com/bubkoo/html-to-image)。这些是实现依据，不是本项目已通过集成测试的声明。

### 5.2 不采用的方案

| 方案 | 不采用原因 |
| --- | --- |
| 只隐藏代码框 | 用户遇到识别错误后仍不会纠正，不能完成已确认的完整体验 |
| 自行实现完整数学编辑器 | 重复实现光标、嵌套结构、矩阵和键盘规则，维护面大 |
| 将所有公式直接变成源图截图 | 可以阅读但失去可编辑结构；无法导出校对后的公式 |
| CDN 编辑器或云端截图服务 | 增加网络依赖和数据外发面，与本机处理边界不符 |

### 5.3 复用与新增边界

- 复用现有模型、公式存储、版本保存、页图与 Word/Markdown 导出。
- 扩展公式卡片、指南和针对性的测试。
- 新增前端可视化编辑及 PNG 生成适配，依赖 mathlive、html-to-image。
- 明确不做：模型训练/替换、公式自动讲解或求解、整篇论文版面重建、账号与云服务、API/数据库迁移、公网发布、Git 提交推送。

## 七、风险与回滚

| 风险 | 缓解与验证 |
| --- | --- |
| 编辑器返回的 LaTeX 与 KaTeX/OMML 支持范围不同 | 用分式、上下标、矩阵、向量与无效输入逐项验证；保留原值、取消和高级源码修复入口 |
| 数学意义被改写或错误沿用已核对标记 | 不使用计算/化简功能；编辑后重置 verified，逐字/逐结构对照原图 |
| 手机键盘遮挡、编辑失焦 | 校对窗内容可滚动，配置虚拟键盘容器；测试手机及桌面焦点 |
| 字体缺失、PNG 空白/截断、下载受限 | 检查同源资源和实际 PNG 像素，预览并提供显式下载；不把下载按钮出现算作落盘成功 |
| 首屏体积增加 | 编辑器和图片工具按需加载，不阻塞普通 OCR；检查构建产物及网络请求 |
| 原图包含敏感内容 | 只从现有同源页图裁切，不上传第三方，不修改原文件 |

回滚：实施前保存受影响现有源码和依赖清单的局部副本；有变更时仅恢复本次修改，保留用户其他改动和文档数据。移除本次新增适配文件后按旧 lockfile 恢复依赖，不重置工作区或清空数据。
