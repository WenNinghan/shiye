# 识页公式识别与校对指南

识页面向论文、教材和讲义中的**清晰印刷公式**，提供学术模式整页扫描和单公式框选两条路线。识别后默认显示课本式公式，**不需要学习 LaTeX 才能阅读和修改**。底层仍保留数学结构，便于继续导出 Word 和 Markdown。

## 先用一分钟学会校对

1. 找到右侧的“数学公式”卡片，先直接阅读排版结果。源码默认折叠。
2. 点“对照 / 放大”：左边是原图局部，右边是识别结果；用放大按钮检查上下标与边界。长公式可横向滚动查看，手机上下排列。
3. 点“修改公式”：点击需要改的字母、分子、分母或矩阵格子，再用键盘输入；也可使用“分式、根号、上标、下标、积分、求和、2×2 矩阵”按钮插入结构。
4. 手机上点“数学键盘”输入数字和符号；窗口可滚动，底部仍能找到操作按钮。“撤销 / 重做”只影响当前编辑草稿。
5. 点“应用修改”才会写回卡片。点“取消修改”后，如有改动，会让你选择“继续编辑”或“放弃本次修改”；放弃不会改变原公式。空占位和无效排版不能应用。
6. 对照无误后勾选“已对照原图核对”，再点击工作台“保存”。修改内容后核对状态会清除，不能把旧确认当成新结果已经正确。

例如矩阵右下角把 `a` 识别成 `d`：打开“修改公式”，在右下角删掉 `d`、输入 `a`，检查预览，再应用、核对、保存。不会自动计算逆矩阵、简化表达式或替你判断哪个字符才正确。

需要专业输入时，展开“高级：公式代码与显示设置”，可以修改或复制 LaTeX、切换行内 / 独立显示。**高级源码直接改动当前文档**，与可视化编辑中的临时草稿不同；仍需保存。

## 一、安装与状态检查

在 Windows PowerShell 中进入项目根目录：

```powershell
./scripts/install-formula.ps1
./scripts/stop.ps1
./scripts/start.ps1 -SkipSetup
```

安装脚本会：

1. 建立独立公式环境，不修改核心 `.venv`；
2. 安装锁定的 PaddlePaddle / PaddleOCR 版本；
3. 下载 `PP-FormulaNet_plus-M` 与 `PP-DocLayout_plus-L`；
4. 预热模型并把本机路径写入被 Git 忽略的 `.data/formula-runtime.json`。

建议预留约 4 GB。若项目盘可用空间不足 8 GB，脚本会选择有足够空间的磁盘；也可显式指定：

```powershell
./scripts/install-formula.ps1 -RuntimeRoot 'G:/ShiyeFormulaRuntime'
```

打开 `http://127.0.0.1:8765/api/formula/status`，确认 `available` 与 `model_cached` 均为 `true`。首页左侧应显示“PP-FormulaNet · 就绪”。普通文档模式不依赖这套环境；公式环境损坏时也不应影响普通 OCR。

## 二、整页自动识别

1. 上传论文截图、扫描页或 PDF，选择“学术公式”。
2. 先完成旋转、裁剪和隐私遮盖，再点击“导入并整理”。
3. 点击“开始识别”。识页先提取正文与简单表格，再定位公式并替换同区域的普通 OCR 乱码。
4. 右侧出现“数学公式”块后，对照左侧紫色框逐项检查。
5. 点击“修改公式”进行可视化校对；应用并确认无误后勾选“已对照原图核对”，再保存。

如果普通模式已经识别完一页，也可以在内容校对页点击“自动找本页公式”。重复扫描会按区域去重，不会无限叠加相同公式；已人工确认的公式不会被自动结果覆盖。

## 三、框选单个公式

整页检测漏掉小公式、行内公式，或自动框包含太多正文时：

1. 点击“框选识别”；
2. 在左侧原图上拖出矩形，尽量贴紧公式外缘，同时完整包含上下标、根号横线、积分上下限和矩阵括号；
3. 点击“识别公式”；
4. 检查实时预览，不准时缩小或调整框选后重试。

框选识别会替换同一区域中未确认的自动公式，但不会覆盖其他位置的内容。

## 四、必须核对的符号

建议按固定顺序检查，速度比从头“看起来像”更可靠：

- 希腊字母与拉丁字母：`ρ/p`、`ν/v`、`μ/u`；
- 正负号、乘号、点乘与等号；
- 上标、下标和积分 / 求和边界；
- 分子分母是否互换，根号横线是否覆盖完整；
- 圆括号、方括号、绝对值与矩阵行列；
- 多字符下标中的花括号，例如 `x_{ij}`；
- 粗体、直立体等语义命令是否符合原文。

模型置信分只反映检测器把该区域视为公式的把握，**不等于 LaTeX 每个字符都正确**。本项目合成验收页的三个公式都被正确定位，但矩阵末项出现过 `a → d` 的字符级错误，因此确认开关不能自动勾选。

## 五、导出行为

| 目标 | 公式结果 |
|---|---|
| 单公式 PNG | 卡片点“公式图片”，检查预览后点“下载 PNG”；白底、2 倍像素，仅包含当前排版公式 |
| Markdown | 行内公式写为 `$...$`，独立公式写为 `$$...$$` |
| Word | 常见结构转为原生 OMML，可在 Word 中点击后继续编辑 |
| TXT | 保留 LaTeX 源码 |
| JSON | 保留 `latex`、`display`、`verified`、来源、坐标和置信分 |
| 图片 / 可搜索 PDF | 画面仍使用原页；可搜索层保存当前 LaTeX 文本，不重新排版画面公式 |

Word 已实测分式、平方根、上下标、积分边界和矩阵。若 LaTeX 使用转换器不支持的宏，导出器会保留源码并给出回退数量；未确认公式也会在导出结果中明确警告。

PNG 适合放进 PPT、报告或聊天；它是图片，不能当作可编辑公式。要继续改结构请选择 Word。PNG 按完整公式生成，不会只截取卡片中露出的部分；过大的公式会提示分段或改用 Word。

部分内嵌浏览器可能把下载保留为 `.tmp` 临时文件。可在独立 Chrome / Edge 中打开本机地址后下载；确认内容确为 PNG 后也可另存为 `.png`。这不是公式图片内容缺失。

## 六、性能与边界

本机 Windows CPU、模型已缓存时，合成验收中单公式框选约 13.8 秒，含三个公式的整页扫描约 12.9 秒；首次进程加载和首次模型下载更慢。数值只是当前机器与样张的运行记录，不是速度承诺。

当前不承诺：手写公式、严重模糊照片、极端倾斜或弯曲书页、超长推导、多栏阅读顺序、任意 LaTeX 宏包、化学结构式以及 100% 符号正确率。遇到这些材料，请优先改善拍摄、分段框选并人工校对。

## 七、故障排查

- **学术公式按钮不可选**：运行安装脚本并重启服务，再检查状态接口。
- **首次识别很久**：查看 `.data/formula-engine.log` 是否正在加载缓存模型；不要连续重复点击。
- **提示超时**：先框选单个公式；仍失败时重启服务并保留日志。公式任务默认上限 240 秒。
- **磁盘不足**：用 `-RuntimeRoot` 指向空间更充足的磁盘；不要把模型目录提交 Git。
- **暂时无法排版**：卡片会显示提示与原图，不把报错代码当作公式。重新框选、可视化修改，或在高级选项检查括号和不支持的命令；有效前不能勾选核对或生成 PNG。
- **编辑器加载失败**：关闭窗口后重试；更新代码后先运行 `cd web; npm ci; npm run build`，再刷新页面。编辑器和字体随项目本机提供，无需外部 API 密钥。
- **Word 里显示 LaTeX 源码**：说明该结构触发了安全回退；依据导出警告逐项简化或改写命令。

可复现验收命令：

```powershell
./.venv/Scripts/python.exe scripts/verify_formula.py
```

机器可读结果保存在 `verification/formula-check.json`，自动定位框、Word 渲染和实际工作台截图位于 `verification/screenshots/`。
